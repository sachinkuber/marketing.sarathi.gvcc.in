# M9 Research Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner enters a brand's website, social links, competitors and documents. Research then runs as one job per source group plus a merge job, and the owner sees a draft brand profile of suggestions with sources to accept, edit or reject. Every web search is counted and costed.

**Architecture:** Two new agents, `research` (one job per source group, using the provider's server-side web search and fetch) and `research_merge` (no tools). Both run on the Phase 1 work engine. The worker learns server tools, `pause_turn` continuation and search/fetch counts. The core stores searches in the model-call ledger and prices them, accepts document uploads, starts research and turns the merged result into profile suggestions through M8's suggestion service. Before anything new runs, the worker refuses a job whose agent files differ from the live release (M8 carried item). The dashboard gains four owner-only screens.

**Tech Stack:** Node 24.20.0 running TypeScript directly, Express 5, PostgreSQL 17 with row-level security, node-pg-migrate SQL migrations, pg-boss, zod, vitest, Playwright, Next.js (dashboard), the pinned Anthropic SDK.

**Spec:** `docs/specs/2026-11-20-phase-2-onboarding-strategy.md` (approved version 1). This plan covers sections 4, 5, 6, 7, 8, 12, 13 and 14, and packages 22, 23 and 29 of section 16, plus the M8 carry-overs recorded in `docs/progress.md` ("Carried to M9") and the M8 whole-branch review (rulings R9, R10). Phase 1 rules in `docs/specs/2026-10-04-phase-1-foundation.md` still hold.

## Global Constraints

- **Where commands run.** Commands run on the development server only. `rsync` the tree to `/opt/mkt-dev/marketing` (exclude `secret-keys`, `2fa`, `node_modules`, `.superpowers`, `.next`), then run `ssh root@<dev-server> '/opt/mkt-dev/run.sh "timeout <s> <command>"'`. Nothing runs on the laptop but git and editors, and that includes prettier. No server address goes in any file or commit. Wrap every server command in `timeout`.
- **Dependencies.** No new runtime dependency except `pdf-lib` (Task 5b). Every dependency stays pinned exactly (`npm run check:pins`).
- **Migrations.** Files are `packages/db/migrations/NNNN_name.sql`, next numbers `0025`, `0026`, `0027`, each with `-- Up Migration` and `-- Down Migration`. Brand-scoped tables follow M8's rules (RLS forced, a single `brand_isolation` policy, composite brand foreign keys, `mkt_app` grants, `select` for `mkt_readonly`).
- **Worker boundary.** The worker never imports `@mkt/db`, `pg` or core code. It reaches data only through core's worker routes with the attempt token.
- **Untrusted input.** Web pages, search results, social bios, documents and owner free text are untrusted (AI-6). They reach the model wrapped and labelled as data, the same way `wrapBrief` works, and are never followed as instructions.
- **Research models and caps.**
  - Research and merge run on `claude-sonnet-5-5`.
  - Tools are `web_search_20260209` (name `web_search`) and `web_fetch_20260209` (name `web_fetch`).
  - Per research job: at most 20 searches and 30 fetches. Per research run for a brand: at most 150 searches.
  - Source groups are exactly `site`, `social`, `visibility`, `competitors`, `documents`.
- **Price per search.** 10,000 micro-USD per search (USD 10 per 1,000). Fetches are counted but not charged. A call with searches and no search price on its `model_price` row is left uncosted (null), never costed as zero.
- **Confidence (spec 8.2).**
  - `found` needs one of: a `site` or `document` source, an `owner_statement`, or two sources at different hosts that agree.
  - Anything weaker is `assumed`. Nothing found is `unknown`.
  - Sources that disagree mean `assumed`, with `why` containing "sources disagree".
- **Source results.** `research_source.result` is one of `read`, `blocked`, `empty`, `error`, `stated` (`stated` is used for owner statements).
- **Documents.**
  - Allowed types are PDF, PNG, JPEG and WebP. The type is checked by magic bytes, not by the header alone.
  - Limits (owner decision 2026-11-20, "add large PDF handling to M9"; replaces the spec's 10 MB):
    - a PDF is at most 104,857,600 bytes (100 MB);
    - an image is at most 5,242,880 bytes (5 MB, the provider's image limit);
    - at most 20 documents and 524,288,000 bytes (500 MB) in total per brand.
  - A PDF over 8,388,608 bytes (8 MB) or over 100 pages is split at upload into AI-ready parts of whole pages, each at most 8,388,608 bytes and 100 pages. The original is kept unchanged. A single page over 8 MB, or a PDF that cannot be parsed (encrypted or damaged), is refused with a message saying how to fix it.
  - The one new runtime dependency allowed in M9 is `pdf-lib` (MIT), pinned exactly, used only in apps/core for splitting (owner approved 2026-11-20).
  - Upload is a raw body with `content-type` set to the media type, plus a `x-file-name` header (at most 200 characters after trimming).
- **Permissions.** Every onboarding route and screen uses permission `onboard_brand` (platform owner only).
- **Audit actions** follow `<domain>.<snake_case_event>`. Detail carries ids, counts and sizes only, never page, document or answer text.
- **Copy.** Dashboard and API errors use plain words and no apologies. An error says what is wrong and how to fix it. Screens work at 390 x 844 with touch.

## Review Focus

- **A group job dies (retries used up).** Research must still merge the groups that finished, and the progress screen shows the dead group as "could not be read". Task 9 test: `a dead group still lets the merge start`.
- **Research is started twice, for example by a double click.** The second start is refused with 409 `research_running` and no second set of jobs is created. Task 8 test: `a second start while running is refused`.
- **A file named `.pdf` that is really HTML.** It is refused with 415 `unsupported_type` and nothing is stored. Task 5 test: `a file whose bytes are not its type is refused`.
- **A `pause_turn` reply.** The worker continues the turn, staying within the remaining search budget, and does not count it as a failure or a retry. Task 3 test: `pause_turn continues with the remaining budget`.
- **A merge result citing a source id from another run or another brand.** It is refused with 422 and writes no suggestions. Task 9 test: `merge refuses a source outside its run`.

- **`researchGroupResultSchema`** (`research_group.v1`, strict):
  ```
  { group,
    sources: { ref: /^s[0-9]{1,3}$/, kind, address: string | null, documentId: string | null,
               result: 'read'|'blocked'|'empty'|'error', extract (≤ 500 chars),
               flagged: { reason: string } | null }[] (≤ 60),
    findings: { key: ProfileKey, proposed, why (≤ 300), sourceRefs: string[], confidence,
                conflict: boolean }[] (≤ 40),
    unsettled: { key: ProfileKey, why }[] }
  ```
  `kind` cannot be `owner_statement`.
- **`researchMergeInputSchema`:**
  ```
  { groups: { group,
              sources: { id: uuid, kind, address, result, extract, flagged }[],
              findings: (as above, but with sourceIds: uuid[] in place of sourceRefs) }[],
    deadGroups: SourceGroup[] }
  ```
- **`researchResultSchema`** (`research.v1`, strict):
  ```
  { suggestions: { key: ProfileKey, proposed, why (≤ 300), sourceIds: uuid[], confidence,
                   options?: { value, tradeOff, recommended }[] (2–3, exactly one recommended) }[] (≤ 40),
    gaps: { key, why }[] }
  ```
  There is no `decision` field anywhere, so a result that tries to decide is refused by the strict schema (half of spec test 43).
- **Request builders**, shared by handlers and eval runners:
  - `buildResearchGroupRequest(agent: LoadedAgent, input: ResearchGroupInput, extra: { pages?: { address: string; kind: string; text: string }[]; documents?: { mediaType: string; base64: string }[] }): ModelRequest`, in `apps/worker/src/agents/research.ts`.
  - `buildResearchMergeRequest(agent: LoadedAgent, input: ResearchMergeInput): ModelRequest`.
  - All page, document and intake text is wrapped as untrusted data.
- **Definitions:**
  - `research`: `jobClass: 'production'`, `resultType: 'research_group.v1'`, `maxTokens: 16000`, `effort: 'medium'`, `tools: [{ type: 'web_search_20260209', maxUses: 20 }, { type: 'web_fetch_20260209', maxUses: 30 }]`, `caps: { searchesPerJob: 20, fetchesPerJob: 30, searchesPerBrandStep: 150 }`.
  - `research_merge`: `jobClass: 'production'`, `resultType: 'research.v1'`, `maxTokens: 16000`, `effort: 'medium'`, no tools.
- **Eval runners.** Evaluation never uses live web, which is the "recorded inputs" ruling. `EVAL_RUNNERS.research` sends the group request with tools removed and the case's `input.pages` and `input.documents` given as wrapped data. Each runner's `inputSchema` is the input schema plus optional `pages` and `documents`.
- **Pinned check semantics:**
  - `flags_source { sourceId }` passes when a `sources[]` entry with `ref === sourceId` (or `id`) has `flagged` not null.
  - `no_third_party_fact` passes when no `found` finding or suggestion rests only on `social`, `search` or `competitor` sources.

  - `document(documentId: string): Promise<{ mediaType: string; bytes: Buffer }>`
